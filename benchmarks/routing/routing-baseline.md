# Routing baseline

Generated by `python benchmarks/routing/route_check.py`; the docstring at the top of
that file is the methodology. This is a **lexical** approximation of routing — stemmed
TF-IDF cosine over skill and command descriptions. It answers "is the right skill
reachable from this phrasing," never "does the model understand it." Behavioural
measurement is a separate question this repo does not currently answer; see
[the project README](../../README.md#what-is-not-measured-does-the-plugin-change-the-answer).

### What changed, and what did not

**Changed:** every skill and command description was rewritten to the formula in
SPEC §3.5 — third-person verb, then two or more `Use when` clauses each carrying a
different slice of plain user vocabulary. `validation-strategy` was merged into
`ds-validate` (the one merge the collision matrix justified; it had also fallen to
#47/47 for its own prompts once `ds-validate` carried the vocabulary).

**Not changed:** no skill was renamed, so every `/ds-*` command, README row, and
external link still resolves. No other merge from SPEC §3.3 was executed.

### Two honest caveats

1. **Alias crediting.** The rank-1 headline counts a skill as correctly routed when its
   own command ranks first instead (`cmd:ds-prep` for `ds-prep`) — same destination,
   different door. The stricter number is reported alongside and is 78.3%. The reference
   implementation this is ported from has no commands in its corpus at all, so its
   published 86% is closest in kind to our strict figure.
2. **Circularity.** The descriptions were tuned against these prompts. The prompts were
   written first, from how users actually phrase things, and no description copies a
   prompt string — but a check whose targets are edited to satisfy it is weaker evidence
   than one held fixed. Tier 3 (behavioral) is the independent test, and it has not run
   yet. Treat 91.3% as "the vocabulary gap is closed", not as "routing is solved".

## What this says

**Headline: rank-1 rate 47.8%** (44/92 positive prompts rank their own skill first).
The reference implementation this check is ported from runs a CI floor of 80% against a
checked-in baseline of 86%. Nearly half of realistic user phrasings do not reach the skill
that owns them.

**Only one real description collision** — `ds-validate ↔ validation-strategy` at 0.546,
below the 0.75 error threshold. Zero pairs are in error range.

That second number matters more than it looks, because **it falsifies the merge-driven
merge-driven diagnosis.** The catalog's problem is not that thirty
descriptions overlap and fight. Measured, they barely overlap at all. The problem is that
they are written in *author vocabulary* and users speak *user vocabulary*, so many skills
are effectively unreachable — merging them would not fix that.

### The five worst, and why they matter

| Skill | Prompt | Rank |
|---|---|---|
| `uncertainty-quantification` | "how confident should I be that model A beats model B" | **46 / 47** |
| `notebook-hygiene` | "make sure this runs top to bottom on a fresh kernel" | **44 / 47** |
| `metric-selection` | "is accuracy the right thing to report for this problem" | **44 / 47** |
| `imbalanced-data` | "only 0.2% of my rows are positive, what do I do" | **41 / 47** |
| `data-science-project` | *the verbatim iteration-2 eval-2 prompt* | **31 / 47** |

The last row is the regression, reproduced deterministically and for free. In iteration-2
that prompt cost twelve behavioral runs and roughly $15 to discover. Here it is a sub-second
assertion.

Rows two through four are worse news than the regression: `metric-selection` and
`imbalanced-data` are the pack's *core claim* on the credit-card-fraud dataset, and neither
is reachable from how a user would actually raise the problem.

### Diagnosed causes

1. **The front door has no trigger vocabulary.** `data-science-project`'s description opens
   "Use at the very start of a tabular ML or data-science task" — no `Use when` token, and
   no overlap with "build me a model", "predict this column", "is it good to ship". Already
   flagged independently by Tier 1 (`tests/test_skill_lint.py`, `description-trigger`).
2. **Formal register beats plain register.** Descriptions say "prevalence-appropriate metric"
   and "leakage-safe validation strategy"; users say "precision or recall" and "will a random
   split leak". The words never meet.
3. **Two attractor descriptions.** `capturing-learnings` and `causal-vs-predictive` appear in
   the top-3 for prompts they have nothing to do with ("speed up this groupby", "plot the
   target distribution"). Their descriptions are lexically generic enough to soak up
   unrelated queries.
4. **Commands compete with their own skills.** `cmd:ds-baseline` outranks `ds-baseline`,
   `cmd:ds` outranks `ds-explore` on an EDA prompt. Commands are in this corpus deliberately —
   the iteration-2 executor reached `/ds` through the Skill tool, so they share the routing
   space whether we model them or not.

### What this changes about the plan

Phase 3's centre of gravity moves from **§3.4 (merge skills)** to **§3.5 (rewrite
descriptions)**. Merging is now justified for exactly one pair on collision grounds; the
rest of the consolidation case has to stand on architecture (stateless vs staged) rather
than on measured overlap, and should be argued or dropped on those terms.

Re-run this check after every Phase 3 commit. The floor to beat is **47.8%**.
